# 重启 dsh web 后的验证清单（2 分钟）

管家插件已写入 web profile 的 bundles。重启后按序核对，任一步不符请把界面文字发我。

## 步骤

1. **重启 dsh web**（用你平时的重启脚本/方式）。

2. **打开**：`设置 → 插件`（左侧设置面板里"插件"那一页）→ 默认停在 **插件配置**。

3. **应看到新增卡片「插件与技能管家」**（在 ego-browser 卡片附近）。
   - 如果没看到：点页面右上 **刷新**（不是重启），再看一次。
   - 仍没有：告诉我，我查 host 侧是否报错。

4. 点卡片里的 **「状态」**，输出应类似：
   ```
   DSH home: C:\Users\ddnin\.dsh
   仓库: (auto)/dsh-sync-manager@main (私有)
   凭据(GITHUB_SYNC_TOKEN): 未配置
   ```
   这行出现 = host 半（/sync/api 网关）已激活 ✓

5. 点 **「盘点」**，应看到：npm 插件 4 个（2 个是内置 @deepseek-ai/*，2 个是 dsh-better-sidebar / dsh-ego-browser）、预置 8 个、skills 5 个、env 名 6 个。

6. 在最下方 **PAT 输入框**粘贴 `ghp_…` → **「保存 PAT」** → 提示"已安全存入本机凭据"。
   （token 只进 `~/.dsh/.credentials.yaml` 的 refs，不会回显、不会上传。）

7. 点 **「同步到 GitHub」** → 首次会自动创建**私有仓 `dsh-sync-manager`** 并上传：
   `catalog.json + README.md + presets/(8 个) + skills/(5 个)`，
   输出形如 `创建 N / 更新 0 / 删除 0 / 未变 0`。

8. （可选）**「仓库差异」** 应显示"未变 = 全部"；**「还原预览」** 显示"无需操作"（本机与仓库一致）。

## 之后可实测的管理链路（都是真实改动，会动本机 profile）

- 新增插件：装个测试包（勾"操作后同步"）→ 验证 catalog 多一条且已推送。
- 删除插件：同上反向。
- 一键更新 / 一键还原：可从仓库把别的机器状态拉回来。

做完把 3/4/7 步的输出发我即可；我据此收尾（实测证据入库 + 目标标记完成）。
